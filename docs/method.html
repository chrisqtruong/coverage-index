2. Collection

  • Sources: the outlets listed in outlets.json, .
  • Each outlet's own feed is used where one works. Where it does not, a Google News search restricted to the outlet's web address is used, and the outlet is marked as such. Outlets with no usable feed are listed as unavailable.
  • Schedule: every 15 minutes (at :07, :22, :37 and :52), by GitHub Actions. Outlets collected through Google News are checked once an hour, because Google blocks frequent requests. GitHub runs scheduled jobs on a best-effort basis, so a run can start late.
  • Requests identify the site: . Requests repeat the previous ETag and Last-Modified values, so unchanged feeds are not downloaded again.
  • Stored per story: headline, link, publication time, position in the outlet's feed, the outlet's section tags, a photo link, and the first characters of the outlet's feed summary. Article text is not stored.
  • Photos are the article's own preview image (the image a link preview shows), loaded from the outlet's site, never copied. Up to article pages are read per run to find one. Stories collected through Google News have no photo.
  • A feed that fails is recorded with its error and time; it does not stop the run. Current status is shown at the foot of the main page.

3. Grouping stories into events

  1. Each headline, plus the start of its summary, is reduced to a list of words: lower case, common words removed, simple endings removed ("protests" and "protest" become one word). Headline words count twice.
  2. Each word is weighted by how rare it is that day (TF-IDF). Words appearing in more than 5% of the day's stories are ignored.
  3. Two stories are compared by cosine similarity, a score from 0 (no shared words) to 1 (identical word lists).
  4. Two stories may join only if all of the following hold:
    • they come from different outlets;
    • their score is at least ;
    • the two groups they belong to also score at least as wholes, which prevents one loose match chaining unrelated stories together;
    • if both groups name places (from a list of country, state and city names), they share at least one.
  5. Strongest matches are joined first. The result is the same every time for the same input.
  6. Week, month and year views join a day's groups to groups up to days apart, with the stricter thresholds 0.35 and 0.30.

Every group on the site lists all of its headlines, so a wrong match is visible to the reader.

4. Categories

A story receives every one of the categories whose rules it matches, from categories.json. For each category the first matching reason is recorded and shown with the story, checked in this order:

  1. the outlet's own section tag in its feed (for example "Politics");
  2. a part of the article's web address (for example /business/);
  3. a listed keyword in the headline.

World: the headline names a country other than the United States. U.S.: the outlet is based in the United States and the headline names no other country, or a U.S. rule above matched. A story that matches no rule has no category and appears only under all categories.

5. Coverage counts

  • The count for an event is the number of different outlets, among those currently selected, that published a story in its group. Each outlet counts once.
  • The comparison figure is the number of selected outlets that published anything in the same day or period.
  • Reprints: when a story's headline exactly matches another story in its group, it is marked as a reprint of the earlier outlet, or of a wire service if one ran it. By default a reprint counts as the outlet it repeats. The "count reprints" option counts it as its own outlet.
  • The "Not covered" list on each event shows the selected outlets that published that day but not this story.
  • Key terms: the words that appear in some headlines of a group and not in others, with the number of headlines containing each. No interpretation is added.

6. Ranking

  • Coverage (default): events ordered by their coverage count, then by most recent story.
  • Outlets' picks: each outlet's top three stories in the order of its own feed. Outlets collected through Google News have no own order; their newest stories are shown and marked.
  • Newest: events ordered by their most recent story.

The count depends on which outlets are selected. The source list contains more outlets based in North America than elsewhere (section 7), so with all outlets selected, events covered by U.S. outlets are more likely to rank high. Selecting a region removes this effect.

    8. How to check this

    • Code and data are public. The repository contains the collector, the page, the rule files and every saved day of data: github.com/chrisqtruong/coverage-index.
    • Every update is logged. Each run has a public log in GitHub Actions and, if anything changed, a commit with a timestamp in the commit history. Latest run: .
    • Results can be reproduced. With the repository downloaded, python3 scripts/collect.py --offline recomputes groups, categories, counts and roundups from the saved stories without contacting any outlet. The output should match the published files exactly.
    • The rules are tested. python3 tests/test_collect.py runs fixed cases, including stories that must join and stories that must not (different countries, same outlet).
    • Reasons are shown. Each event lists every headline, and each category shows the rule that assigned it.

    9. Known limitations

    • Grouping uses shared words. Two reports of one event with different wording may stay separate; two different events with similar wording may join.
    • Category keywords are in English and match whole words only. About a quarter of stories match no category.
    • The source list is not a representative sample of world media. It is weighted toward English-language and U.S. outlets.
    • Google News results depend on Google's index and can be incomplete.
    • Labels describe ownership and format at the time of research and can change.
    • Headlines and summaries are the outlets' own and are not checked for accuracy.
